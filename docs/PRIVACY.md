# 隐私说明

**一句话：你的经期数据存在你自己的手机里，我们不收集、不上传、不分析。**

## 数据存在哪

| 数据 | 位置 | 是否离开设备 |
|------|------|--------------|
| 经期记录（起止日） | 本地 SQLite `period_tracker.db` | ❌ 不离开 |
| 症状记录 | 同上 | ❌ 不离开 |
| 饮食偏好 / 自定义规则 | 同上 | ❌ 不离开 |
| 城市、通知时间、引导状态 | 本地 AsyncStorage | ❌ 不离开 |
| 导出的备份 JSON | 由你选择的文件/应用 | 仅在你自己主动分享时离开 |

App **没有账号系统、没有后端服务器、没有云同步**。卸载 App 会连带删除本地数据库（但不会删除你手动导出过的备份文件）。

## 会发起的网络请求

App 只在两个场景发起网络请求，且都不是为了「上报」：

1. **定位**：调用高德定位 SDK，把设备当前位置换算成城市名。请求发往高德服务器。
2. **天气**：
   - 用城市名向高德地理编码接口换取经纬度（请求含城市名和你的 API key）
   - 用经纬度向 [Open-Meteo](https://open-meteo.com) 请求实时天气（请求只含经纬度与字段列表，**不含任何身份信息或记录数据**）

也就是说：**经期、症状、心情这些数据永远不会出现在任何网络请求里。**

## 我们不做什么

- 没有第三方统计 SDK（无友盟 / 无 Firebase Analytics / 无 Sentry）
- 没有广告、没有画像、没有推送服务端下发
- 不申请通讯录、短信、相册、剪贴板权限
- 不读取设备唯一标识用于追踪

## 权限用途

| 权限 | 用途 | 拒绝后 |
|------|------|--------|
| `ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION` | 自动识别城市以显示当地天气 | 降级为手动选城市，其他功能不受影响 |
| `POST_NOTIFICATIONS` | 每日播报 | 只是收不到通知，App 内功能全部可用 |
| `SCHEDULE_EXACT_ALARM` | 让每日播报准点 | 通知时间可能有几分钟偏差 |
| `RECEIVE_BOOT_COMPLETED` | 重启后重排闹钟 | 重启后闹钟不再触发，需打开 App 恢复 |

## 你的控制权

- **导出**：设置 → 数据备份 → 导出，得到一个 JSON 文件，内容你自己可见
- **删除单条**：日历页选中日期即可取消记录
- **彻底清除**：设置 → 清除全部数据，或直接卸载 App

## 儿童

本 App 不面向 13 岁以下儿童，也不会有意收集其信息（实际上我们收集不到任何人的信息）。

## 变更

隐私策略若有变更会在 [CHANGELOG](../CHANGELOG.md) 中注明。因为不存在服务端，历史上也不存在「历史数据迁移」。
